# Yogurt V4.2 Memory Recall Gate

V4.2 在 V4.0 会话状态和 V4.1 Response Planner 之上增加一个确定性的记忆召回门控。

当前交付是 **shadow-only**：系统会计算本轮是否适合召回、候选属于哪一层、相关性是否足够、是否处于冷却期，并写入结构化审计；不会把记忆正文或门控结果注入 Prompt，因此不会改变酸奶的可见回复。

## 目标

V3 已经可以保存稳定事实、偏好和事件，但“数据库里存在某条记忆”不等于“每次聊天都应该提起它”。V4.2 负责回答：

```text
本轮是否应该使用记忆？
```

第一阶段先校准判断，不直接执行召回。这样可以在真实微信对话中观察误召回和漏召回，而不会干扰现有回复。

## 记忆分层

V4.2 直接复用现有 SQLite 数据，不建立第二套长期记忆库：

```text
Stable Memory
├── facts
└── preferences

Episodic Memory
└── episodes

Temporary State
└── conversation_states
```

- `facts` 和 `preferences` 提供稳定事实与长期偏好候选；
- `episodes` 提供事件和共同里程碑候选；
- `conversation_states` 只提供当前话题、待办、情绪和行为上下文，不作为长期记忆正文。

## 数据流

```text
用户消息
  ↓
V4.0 ConversationStateRuntimeStore
  └── 更新结构化临时状态
  ↓
V4.1 ResponsePlanner（可独立关闭）
  └── 生成回复计划
  ↓
V4.2 MemoryRecallGate（shadow-only）
  ├── 读取当前用户的 stable / episodic memory
  ├── 计算消息相关性
  ├── 结合当前话题与 open threads
  ├── 检查记忆质量、场景风险和冷却
  └── 输出 allow / blocked / none
  ↓
OpenClaw 日志与 SQLite 审计
  ↓
一次正常 Qwen 推理
```

状态更新、Planner 和 Recall Gate 共用一次轻量 Python observer 调用。V4.2 不增加第二次聊天模型推理，也不增加常驻模型或常驻 Python 服务。

## 决策类型

```text
allow
候选达到相关性与质量要求，且没有被风险或冷却规则阻断。
影子模式下只表示“未来可以考虑召回”，当前不会注入 Prompt。

blocked
存在候选，但相关性、场景、情绪、风险或冷却规则不允许使用。

none
当前用户没有可供评估的 stable / episodic candidate。
```

## 评分

候选分数由以下可解释部分组成：

```text
lexical_score      当前消息与记忆正文的词元重合
continuity_score   current_topic / open_threads 与记忆的连续性
quality_score      fact/preference confidence 或 episode importance
explicit bonus     用户明确提出“还记得/上次/之前”时的小幅加分
```

默认门槛：

```text
memoryRecallMinScore = 0.48
```

显式召回请求会降低门槛，但仍要求存在实际相关候选。不会因为用户说“你还记得吗”就随意选择一条无关记忆。

## 保守门控策略

### 允许条件

- 当前消息和候选高度相关；
- 候选质量足够；
- 当前不是低信息确认；
- 当前情绪和场景适合；
- 不在主动召回冷却期；
- 当前用户与会话作用域匹配。

### 阻断条件

#### 低信息确认

```text
好的
嗯
知道了
```

这类消息不应触发系统翻旧账。

#### 情绪不打断

用户处于以下瞬时状态时，未经明确请求不主动召回：

```text
sad
tired
frustrated
```

#### 时刻不打断

`celebrate` 和 `comfort` 轮次默认不插入无关旧记忆，避免把庆祝或安慰变成背景复述。

#### 高风险话题

签证、法律、医疗、账号安全、凭据和支付信息等话题不使用未经请求的主动回忆。显式召回仍只在相关候选存在时开放。

#### 冷却

```text
memoryRecallCooldownTurns = 8
memoryRecallSameMemoryCooldownTurns = 20
```

- 一次允许决策后，默认 8 个用户轮次内不再主动召回；
- 同一条记忆默认 20 个用户轮次内不重复主动召回；
- 显式召回请求可以绕过冷却，但不能绕过用户隔离或候选存在性。

## 隐私与审计

新增表：

```text
memory_recall_conversations
memory_recall_events
```

`memory_recall_events` 只保存：

- `user_id`；
- `conversation_key`；
- `state_version`；
- `turn_index`；
- `decision`；
- candidate layer / kind / source ID；
- score / threshold；
- explicit-request flag；
- bounded reason codes；
- timestamp。

不会保存：

```text
当前用户消息
Prompt
助手回复
记忆正文副本
原始聊天全文
```

Candidate ID 只引用原有 `facts`、`preferences` 或 `episodes` 行，不复制正文。

## 配置

```json
{
  "memoryRecallGateEnabled": false,
  "memoryRecallMinScore": 0.48,
  "memoryRecallCooldownTurns": 8,
  "memoryRecallSameMemoryCooldownTurns": 20,
  "memoryRecallMaxCandidates": 5
}
```

所有 V4.2 配置默认关闭。

开启影子模式：

```bash
openclaw config set \
  'plugins.entries.yogurt-social-injector.config.memoryRecallGateEnabled' \
  'true' \
  --strict-json

openclaw config validate
openclaw gateway restart
```

## 日志

示例：

```text
yogurt-social-injector: v4 memory recall shadow decision=allow layer=stable kind=fact sourceId=7 score=0.731 threshold=0.480 explicit=false cooldown=0 sameCooldown=0 turn=1 reasons=candidate_layer:stable,candidate_kind:fact,gate_allow
```

日志不会输出记忆正文。

常见原因码：

```text
no_candidate
relevance_below_threshold
low_information_turn
emotion_non_interruption
moment_non_interruption
high_risk_topic
conversation_cooldown
same_memory_cooldown
low_memory_quality
explicit_recall_request
candidate_layer:stable
candidate_layer:episodic
candidate_kind:fact
candidate_kind:preference
candidate_kind:episode
gate_allow
gate_block
gate_noop
```

## 只读检查器

查看当前作用域和冷却状态：

```bash
bash scripts/yogurt-recall \
  --pretty \
  status \
  --user-id owner
```

查看决策审计：

```bash
bash scripts/yogurt-recall \
  --pretty \
  events \
  --user-id owner \
  --conversation-key '实际 conversation_key' \
  --limit 20
```

输出中只包含候选引用和评分，不包含用户消息或记忆正文。

## Fail-open

以下故障不会阻断聊天：

- SQLite 读取或写入失败；
- Recall Gate 初始化失败；
- Candidate 评分失败；
- observer 超时或返回无效 JSON；
- V4.2 配置无效。

发生异常时，OpenClaw 保留 V3/V4.0/V4.1 的正常文本路径。


覆盖：

- 高相关 stable fact 允许；
- 无关记忆阻断；
- 简短确认不召回；
- 疲惫用户不被主动回忆打断；

- OpenClaw 只记录 shadow log；
- Recall Gate 不进入 Prompt；
- 多气泡子消息不重复写 assistant 状态。

## 从 shadow-only 进入实际召回的门槛

V4.2 当前不会直接将记忆注入 Prompt。只有在以下条件稳定通过后，才会加入实际 Recall Context：

- 真实微信测试中相关候选稳定允许；
- 无关话题、情绪轮次和高风险场景稳定阻断；
- 用户与会话之间无状态串线；
- 冷却符合自然交流预期；
- 审计中没有原文泄漏；
- V4.0 / V4.1 / V3 回归全绿；
- 功能关闭后立即停止新增 recall 决策事件。
